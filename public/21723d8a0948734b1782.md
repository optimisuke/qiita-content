## はじめに

IBM Concert（IT運用自動化プラットフォーム）の Workflows 機能から Ansible（サーバー自動化ツール）Playbook を実行し、Linux インスタンスに SSH 接続する手順をまとめる。

IBM Automation Library に公開されているテンプレートをベースに試した。

![template.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/184221/2aa96b3c-0470-483a-9a1b-0ccd7d57d4d2.png)

https://automation-library.ibm.com/workflows/Test%20Connection%20to%20RHEL

## 全体の構成

Concert Workflow は直接 SSH を叩くわけではなく、内部の Worker（Ansible 実行エンジン）を経由して接続する。

```
Concert → Worker (Ansible) → SSH → Linux
```

## Workflow の作成

Concert の Workflows 画面から **Create workflow** をクリックし、テンプレートで「Test Connection to RHEL」を検索して選ぶ。

![workflow_library_select.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/184221/654f9a27-94e3-4b3e-9b19-e41ab4cc5a7f.png)

## Authentication の設定

Concert には3種類の Ansible 向け Authentication がある。

| タイプ | 説明 |
|---|---|
| Ansible Tower | Red Hat Ansible Tower（旧製品）に接続して playbook を実行する |
| Automation Platform | Ansible Automation Platform（AAP）に接続して playbook を実行する。Tower の後継 |
| **Playbook** | Tower/AAP なしで Worker から直接 SSH して playbook を実行する |

Tower や AAP を使っていない場合は **Playbook タイプ**を選ぶ。

### 作成手順

Concert UI の Authentications から新規作成する。

![create_authentication.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/184221/b032ccc0-0c7e-452d-be1c-43454df77345.png)

| 項目 | 値 |
|---|---|
| Type | Playbook |
| Service | Ansible |
| Private Key | `cat ~/.ssh/秘密鍵.pem` の中身をペースト |
| Inventory | 下記参照 |

Inventory には接続先のホスト情報を記述する。INI 形式で `[グループ名]` の下にホストを列挙する。ホストグループ名は後述の playbook の `hosts:` と一致させる必要がある。

```ini
[canary]
165.192.130.60 ansible_user=ユーザー名 ansible_port=2223
```

> 秘密鍵は Inventory ではなく Private Key フィールドに入力する。

## Workflow への紐付け

`system/Ansible/Playbook` アクションの `authKey` に、作成した Authentication を選択する。

![authkey_selection.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/184221/fcca4dfa-59f4-4645-bf34-e8aee740de12.png)

ワークフロー実行時に `$auth` 変数として Authentication 名を渡す形になっている。

## Playbook の書き方

Playbook の値はバッククォートで囲む（Concert のテンプレート式）。Object Editor から編集できる。

![playbook_editor.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/184221/3166d884-fa41-43aa-9155-0f8b9253574c.png)

`gather_facts` はデフォルトで有効になっており、ホストの詳細情報を大量に収集する。不要な場合は `false` にすると結果がシンプルになる。

```yaml
---
- name: Test SSH Connection to the remote host
  hosts: canary
  gather_facts: false
  tasks:
    - name: Run pwd
      ansible.builtin.shell: pwd
      register: pwd_result
    - name: Run ls
      ansible.builtin.shell: ls
      register: ls_result
    - name: Show results
      ansible.builtin.debug:
        msg:
          pwd: "{{ pwd_result.stdout }}"
          ls: "{{ ls_result.stdout }}"
```

> `ansible.builtin.ping` は ICMP ping ではなく、SSH 接続と Python 実行環境の確認を行うモジュール。名前に反して「ネットワーク疎通確認」ではなく「Ansible が使える状態か確認」するためのもの。

## ハマりポイント

| エラー | 原因 | 解決 |
|---|---|---|
| `authKey not provided` | `$auth` に値が渡っていない | 実行時に Authentication 名を入力 |
| `$TestSSH is not defined` | Playbook アクションの出力変数参照ミス | 正しい変数名で参照 |

## おわりに

IBM Concert Workflows から Ansible 経由で Linux に SSH 接続し、任意のコマンドを実行できることを確認した。Authentication の設定さえ済めば、あとは playbook を書き換えるだけで様々な操作が自動化できる。
