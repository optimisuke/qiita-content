# はじめに
本記事では、[StepZen](https://stepzen.com/) を用いて PostgreSQL のデータを GraphQL API に変換する方法について解説します。
StepZen は GraphQL や REST API を簡単に連携、統合できる GraphQL API 構築サービスであり、複数のデータソースを一つのエンドポイントにまとめることが可能です。GraphQL スキーマの作成とデータの連携がとても容易で、これによりフロントエンド開発者はバックエンドの詳細を意識することなく、必要なデータにアクセスできます。

ここでの検証は、StepZenの公式ドキュメント（[Getting started with a PostgreSQL database using @dbquery custom directive](https://stepzen.com/docs/quick-start/with-database-postgresql)）を参考にモックの読み取り専用データベースを用いて行いました。
実際に試した際に気づいた点、感じた点を整理したいと思います。

# 使用するデータベースの構成
本記事で使用するデータベースは、下記接続情報で接続できます。

```
host: postgresql.introspection.stepzen.net
database name: introspection
username: testUserIntrospection
password: HurricaneStartingSample1934
```

また、使用するデータベースは、顧客（customer）、住所（address）、注文（order）、商品（products）、顧客と住所の関連を管理する中間テーブル（customeraddress）、注文と商品の間の関連を管理する中間テーブル（lineitem）の 6つのテーブルから構成されています。各テーブルは以下のリレーションで関連しています。

顧客（customer）と住所（address）は多対多のリレーションで、中間テーブル（customeraddress）を通じて結びついています。
顧客（customer）と注文（oder）は1対多のリレーション。
注文（order）と商品（product）は多対多のリレーションで、中間テーブル（lineitem）を通じて結びついています。

# StepZen CLIのインストールとセットアップ
StepZen の公式ドキュメント（[StepZen Install and Set Up](https://stepzen.com/docs/quick-start/install-and-setup)）に沿って、まずはStepZen CLIをインストールします。Node.jsがインストールされていれば、`npm install -g stepzen`でインストールできます。次に、StepZenのアカウントを作成し、ダッシュボードからAdmin Keyを取得し、`stepzen login`コマンドでログインします。



# StepZen を用いた GraphQL API の作成

StepZen の公式ドキュメント（[Getting started with a PostgreSQL database using @dbquery custom directive](https://stepzen.com/docs/quick-start/with-database-postgresql)）に沿って、`stepzen import postgresql`コマンドで、データベースのスキーマ情報からGraphQLの構成ファイルを生成します。

下記のような質問に対して、データベースの接続情報等を対話的に回答していきます。
```
? What would you like your endpoint to be called? api/opining-condor
? What is your host? postgresql.introspection.stepzen.net
? What is the username? testUserIntrospection
? What is the password? [hidden]
? What is your database name? introspection
? What is your database schema (leave blank to use defaults)? 
? Automatically link types based on foreign key relationships using @materializer
 (https://stepzen.com/docs/features/linking-types) Yes
Starting... done
```

ここで、最後の質問である`? Automatically link types based on foreign key relationships using @materializer (https://stepzen.com/docs/features/linking-types)`にYesで答えることにより、外部キー制約によるリレーションを階層化されたGraphQL定義に反映させることができます。
上記コマンド実行後、下記ファイルが生成されます。

```tree
hello-stepzen
├── config.yaml
├── index.graphql
├── postgresql
│   └── index.graphql
└── stepzen.config.json
```

StepZenの設定ファイルとして、`stepzen.config.json`があり、エンドポイント名等が記載されます。

```stepzen.config.json
{
  "endpoint": "api/willing-dingo"
}
```

PostgreSQL接続用に`config.yaml`ファイルが生成されています。これは、後述する`postgresql/index.graphql`から参照されます。
```config.yaml
configurationset:
  - configuration:
      name: postgresql_config
      uri: postgresql://postgresql.introspection.stepzen.net/introspection?user=testUserIntrospection&password=HurricaneStartingSample1934
```

トップのGraphQLスキーマとして`index.graphql`が生成されています。`@sdl`ディレクティブを用いて他のスキーマファイルを指定することができます。StepZenが提供しているディレクティブについては、公式ドキュメント（[GraphQL Directives Reference @rest @dbquery @graphql @materializer](https://stepzen.com/docs/custom-graphql-directives)）に記載があります。

```index.graphql
schema @sdl(files: ["postgresql/index.graphql"]) {
  query: Query
}
```

PostgreSQLのテーブルに対応するGraphQLスキーマ`postgresql/index.graphql`が生成されています。本ファイルには、`@materializer`や`@dbquery`等のディレクティブが使われています。
StepZen を使用して作成された GraphQL API では、以下のようなクエリとミューテーションが生成されます。

* Query
  - id による個別の取得
  - List 全体の取得
  - PaginatedList 範囲指定による取得
  - ViaXXX 多対多リレーションのフィルタリング
  - UsingXXXfkey 外部キーによるフィルタリング
  - UsingXXXidx インデックス付きカラムによるフィルタリング
* Mutation
  - insert
  - delete
  - update

ただし、多対多のリレーションのテーブル（customeraddressやlineitem）を CRUD するエンドポイントはデフォルトでは生成されません。

# APIをカスタマイズする際のポイント
StepZen では、生成された`postgresql/index.graphql`等を修正することでAPIをカスタマイズできます。`@dbquery`ディレクティブを使用して SQL を直接記述することにより、複雑なフィルタリングや結合を行うことが可能です。また、上記スキーマファイルに記載されているように `@materializer` ディレクティブを使用することで、階層化された GraphQL API の生成が可能になります。
詳しくは公式ドキュメント（[Getting started with a PostgreSQL database using @dbquery custom directive](https://stepzen.com/docs/quick-start/with-database-postgresql#extend-the-schema)）を参照ください。
これらのディレクティブを活用することで、API の振る舞いを細かくカスタマイズすることができます。

# 所感
調べた限りでは、StepZen ではバリデーションの処理ができないようです。しかし、スキーマに型を指定することが可能なため、副作用のないデータ取得の Query であれば問題ないと思われます。一方で、Mutation においてはバリデーションが使用できない点が課題となる可能性があります。これに対する一つの解決策としては、StepZenで生成するGraphQL APIは Query のみ使用する、というアプローチも考えられます。バリデーションの実装方法は引き続き調査したいと思います。

また、`@dbquery`や`@materializer`といったディレクティブを使用したカスタマイズは、多様な設定が容易に行えるため、大変便利です。これらの設定は `.graphql` ファイル内で記述できるため、独自の記法を覚える必要がないという点も利点と言えるでしょう。また、宣言的に記載できるため、コードとして管理できる（IaC: Infrastructure as Code）点も交換を持てます。

# おわりに
以上、StepZen を用いた PostgreSQL データの GraphQL API への変換方法について解説しました。生成されたファイルの中身まで見ることで、StepZenの動きを理解できました。他にも有用そうな機能があるので、引き続き調査していこうと思います。
