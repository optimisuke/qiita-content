## はじめに

IBM watsonx Orchestrateで新しく対応されたMCP（Model Context Protocol）接続を試してみました。MCP接続により、外部のツールやAPIをAgentから簡単に呼び出すことができるようになります。

## 前提条件

この記事では、watsonx Orchestrate環境が既に準備されていることを前提としています。まだ環境をお持ちでない場合は、事前にwatsonx Orchestrateの環境を構築してください。

## watsonx OrchestrateのMCP接続の特徴

watsonx OrchestrateのMCP接続は、現状、リモートMCPではなく**ローカルMCP**で動作します。具体的には、`npx`や`python`コマンドで、watsonx Orchestrate上にMCPサーバーを立ち上げて、Agentから呼び出せるようにする仕組みです。

## 実装手順

### 1. Agentの作成

まずwatsonx OrchestrateでAgentを作成します。

### 2. MCP Serverの登録

1. 作成したAgentに対して、MCP ServerをToolとして追加します。
2. 今回のローカルMCPサーバーを利用する場合、**connection情報は不要**です。そのため、接続設定は行わずに進めます。
2. 「Add MCP Server」でコマンドを指定します。
    今回は時間取得MCPサーバーを使用しました。※MCPサーバーの利用は信頼できるものを選択しセキュリティに気をつけてください。以下のMCPサーバーについても自己責任でご確認ください。
    以下のいずれのコマンドでも動作することを確認しました：
    ```bash
    npx time-mcp
    ```
    ```bash
    npx -y time-mcp
    ```
3. 最後にMCPサーバーからインポートされた関数を確認し利用するものを有効化します。

### 5. Behaviorの設定

Agentの動作を定義するBehaviorを設定します。この設定により、MCPサーバーからの応答をどのように処理するかを指定できます。

```
時間を聞かれたら default format で日本の時間を返して
```
![image.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/184221/bc85245b-f32a-421d-a9ad-0708dace51ae.png)

最後にDeployボタンをクリックしてデプロイします。

これで準備完了です。

## まとめ

IBM watsonx OrchestrateのMCP接続機能を使用することで、外部のツールやAPIを簡単にAgentに組み込むことができました。ローカルMCPサーバーとしての実装により、安全で高速な連携が可能になっています。
